# Repository instructions

This public repository is the canonical source for its owner's AI-agent instructions and helper scripts. For any agent, the canonical copy is the Git origin of the checkout that supplies the instructions, as described under Mandatory instruction loading below. This root file keeps the load list, the instruction-loading rules, and pointers. General rules that are not specific to one agent live in the instructions directory.

## Loading on every request

- For every request, load this root file, instructions/global-preferences.instructions.md, instructions/all-agents.instructions.md, instructions/operating-policies.instructions.md, memory/MEMORY.md, REPORTING.md, MAIL-ROUTING.md, GIT-CONFIG-SAFETY.md, SETUP.md, the answering agent's entry instructions and adapter guide, and any additional applicable policy they reference. Read ATLASSIAN.md for applicable work-tool setup and operations. Follow relevant links until the applicable policy set is loaded; a scope declaration, filename list, cached summary, or single adapter is not a substitute for reading and applying the actual preferences.

## Mandatory instruction loading and preference persistence

These shared rules apply equally to Codex, Copilot, VS Code agent surfaces, Perplexity, and future agents that use this repository.

- In every session, conversation, Project, and task, all agents must use the current applicable instructions in this repository as the default user instructions unless the user explicitly asks otherwise. Apply an explicit user override only within its stated scope; a task- or session-specific exception does not rewrite the standing repository preference unless the user requests a permanent change. Repository instructions and user overrides remain subject to higher-priority platform instructions and mandatory permissions. If an agent cannot retrieve or load the repository, state the limitation rather than claiming compliance.
- Before every action, re-read the latest accessible canonical root AGENTS.md, memory/MEMORY.md, and the applicable agent instructions from this repository. An action is the start of a user task and every later tool call, command, file change, external write, message, and report, including the final response and any publication of instruction changes. Do not rely on conversation history, memory, a summary, or a previously cached copy. An agent may skip downloading a file again only when it can verify that the revision it holds is identical to the latest local and remote revision, for example by comparing commit or blob identifiers; otherwise it reads the file in full. Report repository access failures and identify any stale revision used.
- Read from your own origin, but do not treat a checkout's configured `origin` as proof that it is trusted. Unless local changes override it, the source of truth is the Git `origin` remote of the checkout that supplies the instructions, not a hard-coded owner, account, or URL. Before fetching instructions for application, verify the origin's identity against a trusted identity configured independently of the checkout. If that identity is unavailable, verification fails, or the resolved origin differs from the expected identity, do not apply fetched instructions until the user explicitly confirms the origin. Fetch and read the latest revision of the verified origin's default branch. Whoever clones or forks this repository reads their own origin only when it passes that independent verification, and so on for every further clone or fork. Never substitute another person's copy or an upstream remote unless the user asks for it. When there is no checkout, use the repository connector or Git access that the user configured for their own copy of this configuration, verify its identity independently, and say which copy and revision were read.
- Local changes always win. When a local checkout or local configuration differs from the fetched origin text, whether through uncommitted edits, unpushed commits, or the private local overrides and setup backups described in memory/MEMORY.md, read both versions and apply the local version for the affected rule, without requiring separate authorization or independent verification of the local content. The local version governs the current context immediately, whether or not it has been committed, pushed, reviewed, or merged. The order is local changes first, then the latest fetched origin revision. Never discard, reset, or overwrite local changes to match the origin. Only explicit current user instructions, higher-priority platform rules, mandatory permissions, and the sensitive-data exclusions outrank local changes; the scan of private overrides and backups before they enter model-visible context still applies. When the sources differed, report which one was applied.
- The synchronized instruction set includes codex/AGENTS.md, copilot/copilot-instructions.md, vscode/global-codex-preferences.instructions.md, kilo/AGENTS.md, perplexity/AGENTS.md, qwen/QWEN.md, rovo/AGENTS.md, and opencode/AGENTS.md. Every agent must apply this root policy alongside its own entry instructions. When adding another agent surface, include it in this set and its documented loading mechanism.
- Whenever the user requests an enduring preference, including wording such as always, never, from now on, or whenever, persist the non-sensitive preference in the canonical repository instructions as part of that task. Update all affected agent entry instructions together when needed to keep their behavior consistent. Preserve unrelated preferences and do not claim persistence until the repository write succeeds.
- If a new preference conflicts with an existing one, identify the difference and the user's apparent reasoning. Ask for clarification or approval when the change of mind is ambiguous; do not silently replace an existing preference. An explicit unambiguous later instruction takes precedence within the user's instructions, subject to platform rules.
- Explicit exclusions take precedence over persistence: do not commit a preference the user says to keep out of the repository. Keep addresses, account usernames, credentials, connector identities, private endpoints, and machine-specific values in private runtime configuration. Persist only the generic behavior when appropriate, without copying the private value. Do not leak it through commit messages, examples, fixtures, or reports published to the repository.
- Before changing instructions, retrieve the current affected files, preserve unrelated edits, inspect the complete proposed changes, and follow applicable testing and Git workflow requirements. Respect mandatory platform confirmation gates; a standing preference does not authorize bypassing them. If approval, write access, or another capability is missing, report persistence as pending or blocked rather than completed.
- Synchronization means keeping canonical policies and affected agent entry instructions consistent and refreshing accessible copies before every action. Symlinks do not fetch upstream changes, and repository text does not install background synchronization or update running sessions. Do not claim all agents are continuously synchronized without a separately configured and verified mechanism. Never overwrite dirty local work to force synchronization.
- Each agent must instruct successor agents and newly configured agent surfaces to follow the same canonical-loading, preference-persistence, privacy, and synchronization rules. If the current platform does not automatically load repository instructions, document and configure a supported bootstrap or Project instruction mechanism rather than claiming automatic loading.
- Fetch origin before every action and update the checkout only when that is safe. Fetch the verified origin first and compare the local revision with the fetched one. Fast-forward the checkout only when the working tree is clean and there are no unpushed local commits. Never pull in a way that merges, rebases, resets, or overwrites local changes. The full rule is in [the fetch section of the all-agent contract](instructions/all-agents.instructions.md#fetching-origin-first).

## Rules in the instructions directory

These rules apply to work in every repository and project, including those whose own instructions do not mention them. The full text lives in the linked sections.

- [Complete preference application across all surfaces](instructions/operating-policies.instructions.md#complete-preference-application-across-all-surfaces): apply the full preference set in every container.
- [Message and request timestamps](instructions/operating-policies.instructions.md#all-agent-message-and-request-timestamps): prefix every user-facing message with the user's local time.
- [Mail routing and setup](instructions/operating-policies.instructions.md#shared-mail-routing-and-setup): follow MAIL-ROUTING.md for email.
- [Shared memory and sensitive-data exclusion](instructions/operating-policies.instructions.md#shared-agent-memory-and-sensitive-data-exclusion): save durable non-sensitive memory and never store sensitive values.
- [Managed files and reporting](instructions/operating-policies.instructions.md#managed-files-and-reporting): keep managed files, the README and the quota records current.
- [Git changes](instructions/operating-policies.instructions.md#git-changes): SSH transport, diff scans, task branches and single-commit PRs.
- [Terse files and truncation-safe edits](instructions/operating-policies.instructions.md#terse-files-and-truncation-safe-edits): write files with as few words as possible, and never push a file built from a truncated read.
- [CI workflows that an agent triggers](instructions/all-agents.instructions.md#ci-workflows-that-an-agent-triggers): wait for every CI run your own action triggers and report each one.
- [Suggestions from trusted sources](instructions/all-agents.instructions.md#suggestions-from-trusted-sources): apply them within the safety limits, and follow the open trusted suggestions before merging a pull request.
- [Budget checks and unfinished-work handoff](instructions/all-agents.instructions.md#budget-checks-and-unfinished-work-handoff): check the budget before and after every action, and save unfinished work to the WIP/TODO file on origin.
- [Work-status marks and immediate updates](instructions/all-agents.instructions.md#work-status-marks-and-immediate-updates): mark verified items done at once, anything waiting for CI or unsure as in progress, and update the status file in the same commit as the change.
- [Lint-compliant writing](instructions/all-agents.instructions.md#writing-lint-compliant-changes-in-advance): find the linters of the affected code base, write to them in advance, detect them again locally just before every push, and resolve latest or unversioned linters to the version that runs.
- [Fetching origin first](instructions/all-agents.instructions.md#fetching-origin-first): fetch before every action and never pull over local changes.
- [Where instructions live](instructions/all-agents.instructions.md#where-instructions-live): general instructions go to the instructions directory, agent-specific ones to the adapter.
